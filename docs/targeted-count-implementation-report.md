# Targeted physical counts — implementation report

Milestone 8B; software checkpoint verified. Feature development paused at owner request. Implements owner-approved B05 scope and 9 November concurrency/recount rule. No operational migration or operational count execution.

## Workflow

Manager selects an exact existing lot/state and records why the sample/suspicious scope requires counting. An explicit attempt freezes accepted ledger/projection quantities, native expected identities and a movement fingerprint. Native items are explicitly observed by saved Unit Code or DYI:2 input; shared DYI:1 codes cannot stand in for an individual observation. Multiple idempotent chunks support larger lots. Historical lots record quantity/evidence without creating units. Observations are operator-supplied physical-count evidence; ordinary QR lookup, printing and tracking do not become physical verification.

Manager reviews and confirms quantity, unidentified extras, explanation and supporting evidence. MATCHED requires quantity, projection and exact native identity agreement; equal totals with unidentified extras still mismatch. Relevant movements make an attempt STALE without blocking authorized stock operations. Explicit recount retains all earlier attempts. Resolving a mistaken mismatch requires later matching same-scope evidence and a meaningful explanation, with no intervening movement. Genuine discrepancies remain pending correction. No count command changes stock or executes pending authorization.

Admin can review; Production cannot access count administration. Started scopes create closing obligations; the strict daily-close slice will inspect them. This milestone does not claim daily closing is implemented.

## Schema/API

Additive migration `202611090028_targeted_counts`: CountSession, CountAttempt, CountObservation, CountResult, CountResolution and evidence-validation functions/triggers. Accepted history immutable. Database enforces active shop Manager, origin/lot scope, native membership, distinct observations, finalized-attempt fences, derived result status and matching-recount restrictions. Deferred checks require command/audit/outbox evidence and prohibit stock events under the count command.

GET `/v1/count-config`, `/v1/counts?page=1`, `/v1/counts/:id`. Manager POST `/v1/count-sessions`, `/v1/count-attempts`, `/v1/count-observations`, `/v1/count-results`, `/v1/count-resolutions`; all require UUID Idempotency-Key. Same key/input replays frozen result; changed input conflicts. Existing origin-first lock and current account/membership checks serialize acceptance with stock writers. No network calls inside transactions. Decimal-string quantities retain BIGINT precision.
